# Road alerts — official access and local reports

Research checked 30 September 2026. Speed Buddy's existing map/reliability milestone remains in draft PR #1; main is d95c204. Road alerts builds on that branch without replacing Drive, the OSM road engine, MapLibre/OpenFreeMap map or Lufop fixed database.

## Google Maps Platform

The Android Navigation SDK's [real-time disruptions guide](https://developers.google.com/maps/documentation/navigation/android-sdk/real-time-disruptions), updated 15 July 2026, describes route callouts, approaching prompts/audio, report menus and presence voting. Examples include police and speed-camera presence. Reporting/voting is processed by Google and may surface to other Google Maps/SDK users. It requires active route navigation and regional availability; the SDK's availability method must gate a custom report button.

The [coverage table](https://developers.google.com/maps/documentation/navigation/android-sdk/coverage-nav-sdk) marks UK/GB real-time disruptions available, but explicitly says police/mobile-camera types are not available in every disruption-enabled country. That table does not separately promise UK category coverage; verify within the SDK or directly with Google before claiming it.

The documented custom-UI controls configure Google's NavigationView/SupportNavigationFragment, open Google's reporting panel, and notify the app that prompts are visible. The [Navigator reference](https://developers.google.com/maps/documentation/navigation/android-sdk/reference/com/google/android/libraries/navigation/Navigator), [turn feed](https://developers.google.com/maps/documentation/navigation/android-sdk/tbt-feed) and [NavInfo reference](https://developers.google.com/maps/documentation/navigation/android-sdk/reference/com/google/android/libraries/mapsplatform/turnbyturn/model/NavInfo) provide routes, manoeuvres, times/distances and navigation state; no supported incident collection or mobile-camera coordinates/age feed is documented. Therefore these interfaces do not support importing Google live camera reports into Speed Buddy's detector/custom Drive UI. This is an assessment of published interfaces, not a claim that Google has no incident data internally.

[Navigation policies](https://developers.google.com/maps/documentation/navigation/android-sdk/policies) require in-product terms, safe UI and visible Google Maps attribution. Persisting SDK road names/limits outside the user session is disallowed. [Service terms §12](https://cloud.google.com/maps-platform/terms/maps-service-terms) permit use without a corresponding Google map, prohibit use in conjunction with a non-Google map and limit latitude/longitude caching to 30 consecutive days. A generic API key is not permission to copy incidents, persist them as owner data or draw them on the OSM map. No Google-derived data is stored/displayed/exported by this implementation.

For a future separate Google navigation experience, [setup](https://developers.google.com/maps/documentation/navigation/android-sdk/get-api-key) requires a Google Cloud project, billing, enabled Navigation SDK and appropriately restricted API key. [Global pricing](https://developers.google.com/maps/billing-and-pricing/pricing) lists a monthly 1,000-destination free cap and first paid tier US$25 per 1,000 Navigation Request events, with lower volume tiers thereafter; actual agreement/taxes apply. [Billing guide](https://developers.google.com/maps/documentation/navigation/android-sdk/pricing) bills destinations requested, not GPS callbacks. None of this enables a standalone incident feed. No key/billing action is needed for this milestone.

## Waze

The official [Transport SDK guide](https://developers.google.com/waze/intro-transport), updated 10 September 2026, restricts access to approved transport partners. Its listed app data are ETA, route points, next-turn instruction and next-turn distance; server-side traffic-report access and embedded Waze maps/navigation are unsupported. It states support ends **1 November 2026**, recommending [Navigation Connect](https://developers.google.com/maps/documentation/navigation/connect). Connect launches navigation in Google Maps/Waze and supplies authenticated trip tracking; its published workflow does not provide a mobile-camera feed.

[Waze for Cities](https://support.google.com/waze/partners/answer/10618477) is a government/traffic-management data-sharing programme, not an ordinary consumer-app API. The [partner GeoRSS specification](https://support.google.com/waze/partners/answer/13458165) documents approved-area traffic reports with headings, ages and reliability, strictly subject to the partner agreement. That documentation must not be confused with permission for Speed Buddy to access or redistribute a police/mobile-camera feed. Ordinary [Deep Links](https://developers.google.com/waze/deeplinks) open Waze; they return no live reports. No public supported live mobile-camera feed suitable for this app was established for the UK. No Waze endpoint, scraper or private API is called.

## Local report architecture and behaviour

SQLite schema 9 adds only `mobile_reports` and spatial/expiry indexes. All permanent owner/source/correction/suppression tables survive migration. Each report records a namespaced UUID, source (this phone), location, original report time, latest observation, explicit expiry, original lifetime, optional reliable OSM way/name and travel bearing. Stable IDs/source/timestamps permit a later sharing adapter without adding accounts or a server now.

Default lifetime is two hours; Settings → Camera alerts offers 30 minutes, one, two or four hours for **new** reports. Still there renews an active report using its own recorded lifetime and preserves the original time/ID. An expired report cannot be confirmed back into existence. Presence confirmation requires a fresh accurate GPS fix within the 300-yard warning area plus 35m tolerance, checked again at the action; remote map browsing cannot renew a report. Not there removes only that local observation, never a fixed-camera source record or suppression. Repeated taps within 40m/2min on the same road and compatible bearing (35°) reuse the report identity. Maximum 500 observations protects local storage; expired rows are pruned on reporting and periodically during Drive. Clock rollback hides future observations until time catches up; forward changes may expire reports early.

Capture requires a GPS fix no more than five seconds old and accuracy ≤35m. Heading is recorded only at ≥2.3m/s with a valid bearing; otherwise it stays unknown. Road context requires confidence ≥0.55 and location within 20m of the matched geometry. This is a reported **travel direction**, not verified camera enforcement direction; report sheets say so.

`CameraDb.effectiveInBounds` merges fixed layers then appends active mobile observations as `CameraType.MOBILE`. Both Map and Drive use it. Mobile records cannot enter permanent camera/correction/import tables or permanent camera backup. Owner backup schema 7 preserves the fixed/mobile toggles and report lifetime, accepts versions 1–6, and deliberately excludes temporary observations and third-party databases.

The existing CameraApproachDetector handles both categories, with 300-yard approach distance, ≤65° forward bearing and known direction tolerance ±50°. The existing geometry/carriageway filters apply. A reliably stored report road further rejects a confidently different unconnected way when the report lies over 8m off the current way's interior and within 20m of the reported way. Shared geometry points within 3m allow connected continuations. Without reliable road data, heading/distance/direction fallbacks apply; unknown direction cannot guarantee carriageway discrimination. There is no predicted route or enforcement-presence guarantee.

Only one nearest relevant camera warning occupies the existing camera card. Encounter IDs prevent repeated speech; moving outside the existing 850m encounter area permits a later new approach. An active warning survives stopping and weak/lost GPS (distance marked last known), but expiry, Not there or a disabled category removes it. Service ticks check expiry even when stationary/GPS unavailable. Mobile storage is optional to fixed data: malformed observation rows are skipped. Map polls revision/next expiry and refreshes only when needed; report markers are amber rounded diamonds with van/camera glyphs and direction arrows, using the existing clustering budget. A tapped report has its own compact details/actions rather than the permanent-camera editor.

Voice uses existing UK TTS, transient navigation audio focus with MAY_DUCK, release on completion/error/interruption/timeout, and beep fallback. It never changes media stream volume. The phrase is “Mobile speed camera reported ahead”, adding a limit only when confidently known. Fixed/mobile/voice controls are independent; existing speed/red-light and vibration choices remain supported.

Reports, confirmation, expiry and alerts all work offline. Map tiles and external providers are independent. Only local observations are available: this is **not** crowdsourced live camera coverage. No location/report upload occurs.

## Physical acceptance for 0.1.6

Use a passenger or parked setup for phone interaction. Take an owner backup before replacing an acceptance build. Existing release signing instructions are in updates-and-signing.md.

1. Park with precise GPS. Start Drive; tap Report mobile camera once. Expect brief non-modal confirmation. Open Map: find the amber van diamond at the recorded position; open it and verify original time, source, expiry and travel direction (unknown if stationary). My cameras/fixed source counts must not gain a permanent camera.
2. Stop/restart the app before expiry. The report remains. Import the permitted Lufop ZIP while parked; both fixed data and the mobile report remain.
3. To test direction, report while a passenger is travelling steadily in the intended direction, then make a later legal approach along the same road. At about 300 yards expect one spoken mobile warning, distance countdown, age and reliable road name. Repeat in the opposite direction and with the report behind: expect no warning for known incompatible bearing.
4. Select a known pair of nearby parallel roads or divided carriageways with cached road geometry. Approach on the other road; inspect Diagnostics and expect rejection when the match is reliable. Record any false positive with road IDs/GPS accuracy. Unknown or ambiguous heading/geometry is a documented fallback.
5. Stop before passing the report (traffic lights/traffic). The warning stays Approaching without repeated speech; resume and expect continued countdown. Background/resume Drive and repeat. Disable GPS briefly: last-known approach remains, and stale GPS cannot be used to report/confirm a new observation.
6. As a passenger, tap Still there on the approaching card. Verify confirmation age and renewed expiry on Map. Tap Not there; warning and marker disappear promptly, including when stopped. Fixed cameras remain. Repeat with GPS off and Not there: the stale warning must clear on the next service tick.
7. While parked select 30-minute lifetime and create a report. Leave Map open without moving and return after 30 minutes; marker/details must vanish automatically. Drive warning must also expire without GPS movement. Restart after expiry: it must not return. Restore two-hour default.
8. Start music, approach a report and listen: speech requests temporary ducking; music returns to its prior level afterwards. Test TTS unavailable, Stop Drive during speech and background/resume. Verify permanent media volume never changes.
9. While parked toggle Mobile off; fixed camera warning still works. Toggle Fixed off and Mobile on; mobile warning still works and average-speed section context is cleared, including during GPS loss. Voice off silences camera speech while retaining the visual warnings. Re-enable all defaults.
10. Disable network in a visited cached area: fixed/mobile approaches and reporting/confirmation still work. Blank tiles must not disable Drive. Verify 30→20, 20→30, 30→30 and known→unknown transitions still behave as before, with the main limit centred.
11. Check portrait/landscape, large font, light/dark mode and Android back. Report/confirmation buttons must remain reachable and report sheets close correctly. Export/restore backup: new alert settings remain; expired/temporary observations are not restored.

Report actual road/time, GPS accuracy, report ID/direction/age, matched way ID and Diagnostics rejection reason for any discrepancy. Road signs and conditions remain authoritative. Physical GPS, audio player cooperation and background behaviour require device acceptance before merge/release.
