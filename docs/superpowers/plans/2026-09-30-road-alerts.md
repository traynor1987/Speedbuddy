# Road alerts implementation plan

Goal: add temporary local mobile-camera reports to the existing Drive and Map experience.
Architecture: a separate SQLite report layer adapts active reports into Camera instances. Map and Drive consume the same bounded repository and CameraApproachDetector. No external feed is enabled because official Google/Waze APIs do not expose usable raw mobile-camera reports for this UI/map.
Tech stack: Kotlin, Compose, SQLiteOpenHelper, MapLibre, existing Android TTS/audio focus.

- [ ] Add model/policy tests for expiry, confirmation, fresh accurate capture, heading and report road relevance; implement MobileReports.kt and a non-destructive database migration 8→9 with a spatial index. Reports have UUID, local provenance, created/last-observed/expiry timestamps, optional OSM way/name and travel bearing. Default lifetime 120 minutes, choices 30/60/120/240. Confirmation renews that report's recorded lifetime; Not there removes the report atomically. Rapid duplicate reports within 40m/2min on the same road/direction reuse the ID.
- [ ] Adapt reports to CameraType.MOBILE in the common effective repository after fixed-source merging; guard expiry in the detector and cached lists. Persisted reports survive restarts but stay outside permanent camera tables, overrides, imports and owner backup. Preserve fixed-camera filtering and stationary approach continuity. Test behind/opposite/parallel roads, dedup speech, stop/resume, expired/dismissed reports and fixed alert independence.
- [ ] Add one-tap Drive report action (current GPS ≤5s/accuracy ≤35m), compact mobile warning age/road and confirmation buttons. Distinct amber mobile marker/details on Map, automatically refreshed for expiry and repository revision. Keep fixed editors free of mobile type choices. Use existing music-ducking voice with “Mobile speed camera reported ahead”. Add fixed/mobile/voice toggles and compact expiry selector; backup schema 7 preserves new settings while accepting versions 1–6.
- [ ] Add Android persistence, migration and useful UI tests. Run all unit tests, lint, debug build and instrumented tests through established CI; review full diff. Document official capability/cost/terms findings, local-only behaviour and exact physical acceptance steps. Publish logical commits to the existing draft PR; retain physical acceptance gate before merge/release.

Review focus: no report capture from stale/weak GPS; expired reports vanish even without GPS motion; confirmation must not resurrect an expired report; no correction/import can convert mobile reports to permanent cameras; disabling a category clears its warning promptly; reports on a different confidently matched parallel road are rejected while connected next segments remain possible.

Process ruling: the user explicitly directs autonomous implementation and only stopping for credentials/terms/device/service blockers. Proceed without the skill's additional approval pauses. Use native implementation in this session; final review will be a separate pass.
